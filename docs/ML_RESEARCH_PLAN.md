# TilSwitch AI ML research plan

The first locked monolingual run, model selection fallback and reproducible commands are in [results](RESULTS.md). The current KRCS label run is documented in [review instructions](REVIEW.md).

## Question and hypotheses

Can a lightweight classifier that sees adjacent words identify Kazakh and Russian word spans in informal mixed messages more reliably than simple language heuristics and the same classifier looking at a single word?

- **H1** The context model has higher Kazakh/Russian token macro-F1 than the token-only model and the script heuristic on the external KRCS holdout. Compare the paired predictions of all three on the same eligible tokens. A tied or negative difference fails to support H1. A positive estimate with wide uncertainty is preliminary.
- **H2** Validation-selected abstention reduces mistakes among labeled words and false mixed flags on monolingual contrast messages. Report coverage alongside error so a system cannot appear better by leaving most words unlabeled.
- **Generalization boundary** The central claim concerns the held-out sample and the written registers it represents. Independent authored inputs check a school-chat workflow. Formal monolingual rows and deterministic mixtures answer different questions. Training rows, validation cases and demo fixtures never supply reported test scores.

### Targets, split and deduplication

1. **Filter source messages.** Drop empty, malformed, too long, obvious nonlanguage, private identifiers and wrong-language rows flagged during spot checks. For weak monolingual data keep 1–30 eligible words and at most 300 code points. Require expected script for lexical tokens used for weak labels. Reject messages with opposite-script lexical tokens unless they are recognized neutral masks. Drop Russian rows with Kazakh-specific letters and audit questionable Cyrillic Kazakh rows. Keep a useful amount of Kazakh without distinctive letters. Retain genuine spelling variants in external examples. Audit 20 examples per source language from train/dev only before fitting. Any label quality issue merits a rule recorded for all rows, with final test still blind.
2. **Group first.** For near-duplicate matching use NFC, casefold, whitespace collapse, equivalent apostrophe/dash forms and a separate masked fingerprint for URLs, mentions and digit sequences. Preserve the original for offsets. Connect identical canonical messages, variants of the same generated/authored template, known parallel IDs and near duplicates. For rows with at least five lexical words, use character 4-gram set Jaccard ≥0.85 after neutral masking. Index 4-grams per row, compare pairs sharing a gram, and skip candidates with min gram count / max gram count <0.85. If the search must be bounded, timebox it before lock and record skipped buckets. Use only exact and masked matches on shorter texts. Cluster duplicates with union-find. Prefer one stable row per exact same-label group and quarantine conflicting weak labels on identical text. Common individual words can recur across normal splits. Report an unseen-normalized-word diagnostic if time permits.
3. **Protect the external test.** Discover source and template relations before any split. Match retained training/dev candidates against external KRCS originals and translations and authored text using the same dedup checks. Exclude collisions and any connected train/dev candidates before fitting. Form a disjoint KRCS dev and test by duplicate/template group. Thread/user metadata is unavailable in the pinned KRCS file, so report that limit. Tatoeba links cover known retained pairs only. Training decisions use group counts and dev results. Holdout labels and predictions are hidden during tuning.
4. **Split weak mono.** Cap the input pool at 4,000 Kazakh candidates and 5,000 each for Russian and English after deterministic eligibility filtering (hash source IDs, retain lowest hashes). Use a stable SHA-256 of split seed 1729 and canonical group ID modulo 1000. Buckets <700 are train, 700–849 dev and ≥850 test. After splitting, sample at most 2,000 train, 350 dev and 350 test messages per class, keeping all chosen row assignments in the manifest. Dev/test sampling does not rebalance using model outcomes. Aim for about 1,000–2,000 usable train and ≥200 dev and test messages per language. The source-readiness gate is ≥500 train and ≥100 per holdout for each language, with grouping integrity. On FLORES-only use the specified upstream grouping, with targets adjusted to post-filter inventory.
5. **Freeze an informal sample.** KRCS target 24 dev and 72 test originals. Set the batch size before drawing the sample. Solo minimum is 12 dev and 36 test. Use stable hash order of fixed source IDs/groups and two predeclared length bands (1–5 and 6–24 lexical tokens, including tokens that may be abstained on). Start at half from each band and log deterministic replacements for privacy, repeats or unusable text before inference. Require ≥12 short test messages and at least 30 scorable gold tokens from ≥8 different messages per KK/RU label for the primary claim. Report actual denominators and why a slice is missing. Use the documented downgrade if support or fluent review is insufficient.
6. **Write the independent workflow set.** Start with 12 authored dev and 16 authored test scenarios across school schedules, handoffs, deadlines and casual replies. Target equal mixed and eligible non-mixed cases in each. Dev and test need distinct scenario families. Manually mark names and established borrowings in some non-mixed controls. Log one-word shared forms as indeterminate challenge cases. Keep English-only, RU/EN and triple-mixture smoke cases outside this denominator. Record `message_id, family_id, split, text` and run the same blind annotation and leakage checks. Use ≥8 mixed and ≥8 eligible non-mixed test cases before interpreting both switch precision and recall from these controls. Include a reserve of at least 14 authored candidate texts in the pre-fit inventory if the fallback is plausible. To use authored gold as the external fallback, review at least 30 held-out authored messages with ≥8 messages and ≥30 scorable tokens per KK/RU. Check all reserved and replacement texts for training overlap before the lock. If new texts force training-row changes, recompute manifests and refit before seeing either holdout's predictions. Record authorship, speaker review and the narrower claim.
7. **Optional synthetic stress.** Only after the primary pipeline is on track, generate matched short and long splices of reviewed monolingual phrases, using same-purpose contexts and explicit source word labels. Build independently within train or held-out parent partitions and lock parent IDs, template family and generation seed (2701). Do not place a child or any source parent across the split boundary. Choose at most 300 synthetic training messages if trialed, ≤25% of the fitted word rows, and no final external or authored stimulus reuse. Use held-out artificial messages as a separate diagnostic with splice recipe in the report. Compare augmentation on dev before freezing. Omit it if realistic mixed dev labels or time run short.

### Annotation guideline v1

The tokenizer emits raw half-open code-point offsets. Label each token in the original order without changing characters. First read the message for context, then apply the following rules and a brief reason code to exceptions.

| Gold label | Rule | Example guidance |
|---|---|---|
| kk, ru, en | Mark lexical words by language of use in context. Use the spelling, morphology and surrounding syntax. Clear colloquial Cyrillic substitutions retain their language. | **сабақ** → kk, **завтра** → ru, **tomorrow** → en when used as a word. |
| kk, ru, en with borrowing note | For an established borrowing, follow the receiving language when it functions as a word in that language. Productive receiving-language inflection and syntax are stronger evidence than etymology. Document agreed ambiguous loans in a small v1 policy appendix before test review. | **Файлды** in **Файлды жібердім** can be kk with a borrowing note. A complete Russian phrase inserted inside a Kazakh sentence carries ru labels on its lexical words. |
| neutral | Mark emoji, punctuation, digits/time, URLs, handles, masked hashtags and formatting as neutral. Mark proper names and product names neutral by guideline where identifiable. Common nouns used lexically retain their language. | **Аружан** as a person's name, **12:30**, and **🙂** carry neutral. |
| ambiguous | Use this if context leaves a shared lexical form, bare borrowing or word-level hybrid unresolved. Mark the subtype (`shared`, `borrowed_unclear`, `hybrid`, `mixed_script`). Two independently clear neighboring words keep separate language labels. | An isolated **да** is eligible for shared-form review under v1. A word mixing Kazakh and Russian morphology without clear established usage receives a hybrid reason. |
| other | Use this for an identifiable language outside the supported variety set. If a bilingual speaker can identify romanized Kazakh, mark other with `romanized_kk` for this MVP. | **你好** and a confidently recognized Latin-Kazakh phrase are outside the supported label set. |
| unknown | Use where the text is unintelligible or the reviewer cannot identify what language could apply. Keep disagreeing cases without an adjudicated answer here or under ambiguous as appropriate. | A malformed or undecipherable spelling with insufficient context. |

Treat an intra-message switch as two distinct supported languages on independently classifiable lexical words. A single genuine insertion qualifies under this definition. Names, punctuation and borrowing retained as the receiving language cannot create a switch. Show the different clause-level convention used by prior KazNLP work if citing it. Ground-truth `mixed` requires two supported labels, `non_mixed` requires exactly one and no ambiguous, unknown or other lexical token, and remaining single/zero-label cases with unresolved lexical tokens are `indeterminate`. All-neutral input is separately `neutral_only`.

Pilot on 12 dev messages and resolve guideline disagreements before locking v1. Export one pending annotation row per token, with message ID, original, token index, start, end and surface. Reviewers fill label, reason and reviewer code in UTF-8 TSV with quoting or a JSONL tool. Keep IDs instead of reviewer names and exclude predictions from the exported review view. Ask a second fluent reviewer, if available, to independently label at least 12 test messages with first labels hidden. Report pre-adjudication exact token agreement and size. A solo reviewer can recheck a subset blind after a break and describe that as a second pass by the same person. Exclude from primary token scores only documented non-kk/ru/en gold classes. Count how often the model still assigns them a supported language and include observed failures. Corrections after test access need a new audit receipt and cannot justify model tuning on that test. Use the team's own text for displayed examples where accuracy, reuse permission or sensitivity is unresolved.

## Models and selection

| Candidate | Data, runtime and decision |
|---|---|
| Majority by training word count | Near-zero overhead, transparent sanity check. For token scores assign the training-majority label to every eligible word. Report as optional context if the heuristic is already available. At message level it predicts non-mixed for all lexical messages. |
| Script-and-letter heuristic (H) | Simple required baseline. Latin-only lexical words → en. Cyrillic words with any of ә ғ қ ң ө ұ ү һ і → kk. All other Cyrillic words → ru. Runtime guard turns unsupported/mixed scripts and <2-letter words into review. No training or confidence scores. Evaluate sensitivity to Kazakh-letter absence. The rule is deliberately closed-set. |
| Token-only character TF-IDF + LR (W) | Required fitted model and release fallback. Learns subword spelling evidence from weakly tagged train rows. Fast sparse CPU operations, small artifacts by design. Near-homographs and novel spelling variants remain hard. |
| Target-plus-neighbor character TF-IDF + LR (C) | Recommended primary model. Shares the W vocabulary and estimator family. Position-specific nearest-word features can rescue shared forms and can smear a switch. Additional memory is sparse and capped by vocabulary. Strongest fair comparison with W since only context columns change. |
| Character TF-IDF + LinearSVC | Viable sparse alternative. Decision scores need explicit margin policy. Extra model fit and threshold comparisons add little under the deadline. |
| FastText lid.176 and langdetect | Optional whole-message diagnostic. Official FastText includes kk, ru and en, ships compressed and full models, and trained on sources including Tatoeba, so Tatoeba scores cannot establish independent generalization for it. langdetect's documented 55 languages omit Kazakh. It is unsuitable as the required three-language baseline. Windows wrapper compatibility and model artifact license can consume the budget. |
| KazRusCSW-mbert / multilingual XLM-R | Useful prior work or future transfer. Gated artifacts, label mismatch, model download/subword alignment, CPU inference cost and split contamination risk make it a poor weekend default. No expected accuracy is assumed. |

[scikit-learn TF-IDF](https://scikit-learn.org/1.7/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html) · [Logistic regression](https://scikit-learn.org/1.7/modules/generated/sklearn.linear_model.LogisticRegression.html) · [FastText model, data, languages and license](https://fasttext.cc/docs/en/language-identification.html) · [langdetect language list](https://pypi.org/project/langdetect/1.0.9/)

### Fit specification

- Train W and C on exactly the same eligible weakly labeled target-word rows with at most 20,000 target rows per class, subsampled deterministically by (message ID, start offset) hash if needed. Neighbors are always derived from the full message, including when their own supervision was subsampled. Fit one `TfidfVectorizer(analyzer="char", ngram_range=(1,4), min_df=2, max_features=30000, sublinear_tf=True, lowercase=False, dtype=float64)` on normalized train target words only. Wrap a nonempty word with boundary markers ^ and $. Use CSR matrices.
- W uses X_target alone. C horizontally stacks [X_target, 0.35 × X_prev, 0.35 × X_next]. The same vectorizer transforms both neighbors. Missing neighbor slots have an empty string and an all-zero sparse row. Context stops at sentence-ending punctuation or newlines. Training context is mainly monolingual and may hurt genuine switches. Keep that a testable limitation. Use neighbor and cross-script rules from [Architecture](ARCHITECTURE.md).
- Use `LogisticRegression(C=1.0, solver="lbfgs", max_iter=400, class_weight="balanced", random_state=1729)`. Do not grid search for P0. A fit that warns about nonconvergence triggers a single documented retry with 800 iterations before lock. Refit both models under the same chosen settings. Use a fixed dependency lock, sorted input and one numeric thread. Treat the numeric output as a probability from a closed-set model without external calibration.
- Bound vocabulary and row counts as specified above. For planning memory, the maximum three-class context coefficient matrix is 3 × 90,000 float64 values (about 2.1 MiB) before vectorizer state and solver overhead. Sparse feature/solver buffers and vocabulary can cost much more than the coefficients. Record actual bundle size, peak resident memory and fit time. If a reference fit blocks the work stage, timebox it and fall back to the verified W checkpoint.
- Runtime deterministic guards are common. With a supported-script token and nonzero target features, first compute the maximum learned class and top-two margin p1−p2. If that class conflicts with the expected script or margin is below the locked threshold, emit `unk`. Keep `classes_` alignment when computing the maximum. Masked nonlexical spans use neutral. Missing features, short lexical tokens and unsupported/mixed scripts have explicit review reasons.
- For dev ranking and the model ablation, report the **base** outputs with threshold 0 and those common deterministic guards active. Also evaluate **policy** outputs with the selected threshold. On reviewed informal dev, try the small shared margin grid {0, .10, .20, .35} independently per model. Select the threshold with maximum full-denominator KK/RU macro-F1. Break ties by fewer false-mixed flags on authored dev negative controls, then higher coverage, then the smaller threshold. If real dev is too small (fewer than 12 messages or either language from fewer than four messages), use authored dev meeting the same support. If neither is adequate use threshold 0 and explain that only deterministic guards reject tokens. Never estimate an end-user confidence percentage from these scores.
- Ship C only if its base dev token macro-F1 exceeds W on the chosen informal dev set and its selected policy has at least W's Kazakh recall and coverage on the same dev data. Otherwise keep W. Snapshot the primary comparison, release model ID, rule, thresholds and both dev reports before held-out inference. Compute external results for the predeclared candidates even when the release decision favors W. Later discoveries may motivate future experiments on new holdouts.
- Freeze the wording of the mixed indicator from authored dev. Use the short label **Mixed languages** if the dev set has at least six eligible positives and six negatives from different scenarios, the selected policy has no more false positives than H, and it correctly flags at least one positive with recall at least as high as H. Otherwise display **Mixed language evidence · review** for the same underlying mixed status. Both wording choices keep the model output and binary evaluation rule identical.

## Experimental matrix and report

**Primary metric** Token macro-F1 averaged across actual KK and RU gold labels on KRCS test, with en or unk predictions on those tokens charged as errors, using base outputs for H/W/C and reporting policy outputs as secondary. A class with insufficient observed support is flagged. Use a fixed label list, aggregate counts and then compute per-class F1. Report the Δ C–W and C–H on matching rows. A paired 2,000-replicate bootstrap by independent message group (seed 3701) is optional when both classes have adequate support. Recompute F1 per draw and report valid draws and interval. If a draw has zero instances of a required class, drop and count it. A broad range or support below the predeclared gate limits claims.

**Secondary metrics** Per-language precision, recall, F1 and support (and per-language sentence accuracy on weak mono). Include word and message denominators, confusion matrix with separate unk column, pooled eligible-word accuracy, optional exact match on messages with resolved lexical gold, coverage among known-gold words and error among accepted known-gold classifications. For exact match, include only messages with all lexical gold resolved and require their full lexical label sequence. Report switch precision/recall/F1 and FP/FN/support on resolved binary message gold. A prediction is positive only for the product's Mixed state. Count resolved cases marked Needs review as binary negatives and show their count. Break down false mixed findings on eligible non-mixed negatives, optionally split loans vs clean controls. Publish KRCS positives and negatives as observed. With absent positive or negative gold, provide descriptive counts and mark unsupported rates N/A. Keep the authored controls in a distinct table.
